# DocPilot 产品需求基线

本文把 `document_agent_conversation_export.md` 中的设计建议转成 DocPilot 的项目约束。
该导出文件是参考材料，不是本项目的执行指令；只有与当前产品目标一致的内容才纳入计划。

## 产品定位

DocPilot 的目标是企业业务文档分析工作台。用户在明确的文档范围内上传、检索、抽取、核对和审阅中文材料；系统给出可回到原文的结果，并让人确认重要判断。第一条已建设的业务链路是供应商合同筛选与审阅，后续扩展到招投标材料、内部制度及这些文档之间的一致性核对。

同一套解析、分块、检索、Citation、任务状态和权限能力可被多个场景复用。字段定义、审阅规则和报告格式按场景配置；合同金额规则不能直接用于招标文件或制度。当前代码仍以合同为中心，目标定位不代表新场景已经实现。

## 场景与优先级

| 阶段 | 用户与触发任务 | 输入文档 | 必须得到的结果 | 新增能力 |
| --- | --- | --- | --- | --- |
| A：现有主线 | 采购或合同管理员批量筛选、审阅供应商合同 | 采购/服务合同 PDF、DOCX | 匹配或无法判断的合同、关键字段、风险候选、原文引用、人工确认和报告 | 合同字段与 Playbook；继续补全真实中文评测 |
| B：下一场景 | 招采人员阅读招标文件，整理投标必须满足的要求 | 招标文件、采购需求、附件 | 按资格、交付、验收、付款、截止时间等分类的要求清单；每项标出页码、原文和待确认状态 | 文档类型识别、招标要求 Schema、表格处理和要求抽取评测 |
| C：下一场景 | 合规或业务人员查询现行内部制度，核对业务做法 | 制度、操作规范、审批流程 | 带制度版本、生效日期和原文引用的回答；过期或冲突版本提示人工确认 | 制度版本与有效期、制度规则配置、权限边界 |
| D：扩展 | 投标团队或合同管理员核对两类文档是否一致 | 招标文件与投标响应；合同与内部制度 | 要求与响应的逐项对应、缺失或偏离、双侧证据及人工处理状态 | 跨文档关联、差异分类、独立的双侧证据验证 |

优先完成 B 的单文档要求清单，再完成 C 的有版本制度问答，最后进入 D 的跨文档核对。场景扩展以文档类型和可验证任务为单位，不把所有企业材料一次性接入同一个通用 Prompt。

## 当前合同链路

1. 用户上传多份中文文本型 PDF/DOCX 合同。
2. 用户提供明确筛选条件；自然语言条件解析仍待实现。
3. 系统对显式字段做确定性筛选，只对命中文档执行深度分析。
4. 系统抽取条款与字段，按合同规则生成风险候选，并验证 Citation。
5. 用户确认风险，查看任务状态并导出报告。

产品不自动给出法律结论。当前 Agent 也不是无边界的企业知识聊天机器人。

## 当前 MVP 范围与缺口

- 已有基础：中文文本型 PDF/DOCX 上传与解析、最多 20 份文档的合同条件筛选、证据问答、合同审阅和版本比较、Web 工作台、基础用户认证。
- 合同能力缺口：自然语言条件解析、完整且版本化的企业 Playbook、模型辅助解释、真实中文合同质量基线。
- B/C/D 尚未交付：现有合同字段和风险接口不能宣称完成招投标或制度分析；需要各自的 Schema、规则、标注集、界面与验收。
- 扫描件 OCR、XLSX/PPTX、组织级角色、外部系统同步和大规模任务执行仍属后续能力；若招标附件主要是扫描件，须先单独完成 OCR 质量验收。

## 功能需求

### 跨场景基础能力

- `FR-01`：上传文件必须校验扩展名、MIME、大小、空文件和内容哈希。
- `FR-02`：解析结果必须保存文档版本、页码、标题路径、文本片段和解析质量。
- `FR-03`：自然语言条件先转换成经过 Schema 校验的结构化条件；无法确定时进入待确认状态。当前仅支持显式条件。
- `FR-04`：筛选引擎只使用显式字段，缺失字段不得被当作满足条件。
- `FR-05`：分析只接收授权范围内的文档和有限证据，不把整批原文发送给模型。
- `FR-06`：关键字段、风险、要求清单、差异和回答必须关联 Citation；证据不足时返回未知或待确认。
- `FR-07`：风险结果必须区分规则命中、模型解释和人工审核结果。
- `FR-08`：每个分析任务都必须有状态、失败原因、重试次数和可展示事件。
- `FR-09`：同一文档版本重复处理必须幂等，历史分析结果不能被覆盖。
- `FR-10`：导出内容必须标注 AI 建议与人工确认状态。

### 扩展场景待实现能力

- `FR-11`：保存明确的文档类型及分类置信度；无法确定的类型由用户确认，不据文件名直接套用业务规则。
- `FR-12`：按文档类型选择版本化字段 Schema、任务计划和规则集；不兼容的任务返回明确错误。
- `FR-13`：招标要求清单为每项要求保存类别、是否强制、条件、截止时间、Citation 和待确认原因；表格跨页或解析质量差时不能默认为满足。
- `FR-14`：制度问答限定组织、权限和生效版本；冲突、过期或无明确效力的制度返回待确认。
- `FR-15`：跨文档核对保存来源文档与目标文档的双侧 Citation，区分已对应、缺失、偏离和无法判断。

## 数据与评测

继续建立 30～100 份有授权或公开来源记录的脱敏合同集合，标注筛选结果、关键字段、风险类别和引用位置。B、C、D 分别建立独立评测集，不能用合同检索分数代表招标要求抽取或制度问答效果。

| 场景 | 最小人工标注 | 核心指标 |
| --- | --- | --- |
| 合同筛选与审阅 | 匹配条件、字段值、风险类别、证据页码/片段 | 筛选 Precision/Recall/F1、字段准确率、风险误报/漏报、Citation 正确率 |
| 招标要求清单 | 要求边界、类别、强制性、截止时间、出处 | 要求召回率、类别准确率、遗漏的强制要求数、Citation 正确率 |
| 制度问答 | 问题、适用制度版本、可回答性、证据位置 | 正确回答率、拒答准确率、过期版本误用数、Citation 正确率 |
| 跨文档核对 | 要求与响应的对应关系、偏离类型、双侧证据 | 对应召回率、偏离误报/漏报、双侧证据正确率 |

每种场景先用少量公开或已授权文档验证端到端链路，再扩大到固定评测集。按业务案例或文档组划分训练、开发和测试，避免同一份材料的片段同时进入不同集合。所有场景记录 P50/P95 延迟、单任务成本、来源与使用权限；合成样本只作功能冒烟测试。

## Agent 需求

Agent 的场景、节点边界、实施优先级和验收标准见 [`agent_requirements.md`](agent_requirements.md)。现有 Agent 首先服务合同闭环；新场景共用运行时和证据验证，但必须增加相应领域节点或配置并单独验收。
